# /insight-gathering — KOL Plans Are Really Insight Plans

> The best KOL plans don't start with a list of experts. They start with a list of **unanswered questions**.
> Activity plans produce touchpoints. Insight plans produce **better decisions**.

## WHEN TO USE
- Designing a KOL plan, advisory board, or field-medical plan.
- Auditing a plan that lists experts, tiers, interaction targets, meeting schedules (= activity).
- Any time someone asks "who should we engage?" — flip it to "what do we need to understand?"

## THE INVERSION (the whole idea)
| Traditional KOL plan → activity | Insight-driven plan → decisions |
|---|---|
| List of experts | What do we need to understand? |
| Tier rankings | What assumptions need testing? |
| Interaction targets | What decisions need informing? |
| Meeting schedules | Who can help answer them? |

Experts are named **last**, only after the question and decision are clear.

## THE STEPS
1. **Surface the decisions.** List the real, pending strategic decisions (launch sequencing,
   positioning, evidence-gap, market entry). No decision → no insight needed.
2. **Write the question bank.** For each decision, the unanswered questions that would change it.
3. **Name the assumptions under test.** What are we currently *assuming* that, if wrong, breaks the plan?
4. **Prioritise** by decision-impact ÷ effort. Apply the T-Bone test (shifts strategy / narrative /
   priorities? 0/3 = drop). Pick the one question to pursue first.
5. **Map minimum experts.** Only now: which KOL is uniquely able to answer *this* question? Smallest set.
6. **Design the capture loop.** How each insight is recorded (question · assumption · insight · decision ·
   confidence · source), then **routed** to the decision-owner with a recommended action.

## OUTPUT TEMPLATE
```
INSIGHT PLAN — <topic / product>
DECISIONS PENDING:        [the real decisions this plan must inform]
QUESTION BANK (ranked):   Q1 … Qn  (impact ÷ effort)
ASSUMPTIONS UNDER TEST:   [unvalidated beliefs that could be wrong]
DECISION EACH INFORMS:    [Q → decision]
MINIMUM EXPERTS:          [only those who can answer the top questions]
CAPTURE & ROUTE LOOP:     [how insight is logged and sent to the decision-owner]
PURSUE FIRST:             [the single highest-leverage unanswered question]
```

## COMPLIANCE
Non-promotional scientific exchange (UCPMP/OPPI). Reactive, balanced, INN names. Anything drifting
promotional → `@compliance-redteam`.

## STOP CONDITION
Done when every question maps to a decision, the top question is chosen, and the minimum expert set +
capture loop are defined. If the plan still reads as a list of names and meeting counts, it's not done.
